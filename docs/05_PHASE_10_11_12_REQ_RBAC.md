# Phase 10, 11, & 12: Functional Requirements, NFRs, & RBAC Matrix

## Project: Nursing Administration Portal
**Client:** Jazan Specialty Hospital

---

## Phase 10: Detailed Functional Requirements (FRs)

### 10.1 Authentication & User Management
*   **FR-1.1:** The system shall integrate with Firebase Authentication (Email/Password or Enterprise SSO if provided).
*   **FR-1.2:** Users must be required to reset their password upon first login if created by an admin.
*   **FR-1.3:** The user profile must include: Full Name, Employee ID, Email, Phone, Department, Role, and Avatar.

### 10.2 Global Search Engine
*   **FR-2.1:** A persistent search bar must be available in the application header.
*   **FR-2.2:** Search must query across News, Policies, Departments, and User Directory simultaneously.
*   **FR-2.3:** Search results must respect RBAC (users cannot search/see draft policies or restricted admin areas).

### 10.3 Dynamic Content Rendering
*   **FR-3.1:** The frontend must render rich text (HTML/Markdown) generated by the Admin Panel WYSIWYG editor safely, sanitizing against XSS attacks.
*   **FR-3.2:** The system must support embedding external content (e.g., YouTube training videos, Google Forms for surveys) within standard pages.

---

## Phase 11: Detailed Non-Functional Requirements (NFRs)

### 11.1 Availability & Reliability
*   **NFR-1.1 (Uptime):** The system shall target 99.9% uptime, leveraging fully managed serverless infrastructure (Cloud Run / Firebase).
*   **NFR-1.2 (Disaster Recovery):** Database snapshots must be taken daily and retained for 30 days.

### 11.2 Interoperability
*   **NFR-2.1:** The system architecture must expose secure RESTful APIs to allow future integration with the hospital's main HIS or HR systems.
*   **NFR-2.2:** Data export features (CSV/Excel) must be available for all data tables (e.g., Department statistics, user lists).

### 11.3 Localization
*   **NFR-3.1:** The UI must be fully localized for Arabic (primary) and English (secondary). Dates must support standard Gregorian formats localized to `ar-SA` (e.g., 6 يوليو 2026).

## Phase 12: Roles & Permissions Matrix (RBAC)

### 12.1 Defined Roles
1.  **System Admin (Superuser):** IT/System administrators.
2.  **Portal Manager:** DON or delegated senior administration.
3.  **Department Head:** Managers of specific clinical areas.
4.  **Standard User:** Registered nurses, trainees.

### 12.2 Permissions Matrix (Excerpt)

| Module / Action | System Admin | Portal Manager | Department Head | Standard User |
| :--- | :---: | :---: | :---: | :---: |
| **System Settings** | Create/Read/Update/Delete | Read | Denied | Denied |
| **User Roles/Creation** | Create/Read/Update/Delete | Read | Denied | Denied |
| **News / Announcements**| Create/Read/Update/Delete | Create/Read/Update/Delete | Read | Read |
| **Policies (Publish)** | Create/Read/Update/Delete | Create/Read/Update/Delete | Read | Read |
| **Dept Staff Roster** | Create/Read/Update/Delete | Read | Update (Own Dept) | Read (Own Dept)|
| **Recognition Nominate**| Create/Read/Update/Delete | Create/Read/Update/Delete | Create (Own Dept) | Read |
| **View Audit Logs** | Read | Denied | Denied | Denied |

*Implementation Note: This matrix will be enforced both at the UI routing level (React Router guards) and at the database level (Firestore Security Rules).*
